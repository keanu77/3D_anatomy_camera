# Individually identified body source surfaces

`tools/build_individual_body.py` builds the additive `public/anatomy/individual-body.json` and `.bin` pair from the same checksum-pinned BodyParts3D 3.0 source used by the existing body and muscle bundles. It does not modify the existing head, body, muscle, joint or nerve assets. The detailed meshes retain original parent names and local reference frames, allowing the runtime to replace a regional surface while inspection is enabled.

## Coverage and identity

The bundle contains 36 parent meshes and 398 exact source OBJ identities:

| Source surface scope | Components |
| --- | ---: |
| Skeletal bones | 119 |
| Sternum parts: manubrium, body, xiphoid process | 3 |
| Named muscle surfaces | 214 |
| Named muscle heads or subdivisions | 60 |
| Indivisible source muscle aggregates | 2 |

The skeletal scope is exactly the existing `spine`, `arms` and `legs` source coverage, including C3–C7, thoracolumbar vertebrae, sacrum, ribs, shoulder and pelvic bones, limb bones, and feet. It excludes organs, the original head/hands, and C1/C2 outside the body bundle. Muscle coverage preserves all 276 existing muscle source components and its previously documented exclusions. These are source-component counts, not a claim of complete anatomy or 276 distinct whole muscles.

Every part's `id` and `name` are the pinned source element ID and exact English parts-list label. Side is taken from that label and checked against the original geometry's X centroid. No source identity is estimated from regional position or generated by reflecting the other side.

The 60 muscle heads/parts remain selectable under their exact component names. Fifty-six have validated membership in 24 sided whole-muscle groups. `wholeMuscleId`/`wholeMuscleName` retain the real source family concept; those concepts are often bilateral, so consumers must group by **`wholeMuscleId` plus `wholeMuscleSide`**. The four extensor carpi ulnaris heads (`BP44`, `BP45`, `BP46`, `BP47`) have exact source names but no usable whole-muscle hierarchy in this release, so no whole-muscle membership is asserted. The three sternum components similarly retain their element IDs while recording source-validated `wholeBoneId: FMA7485` and `wholeBoneName: sternum`.

Two source objects cannot truthfully be represented as single named muscles:

| ID | Exact source name | Scope |
| --- | --- | --- |
| FMA74140 | set of dorsal interossei of right foot | `source-aggregate` |
| FMA74141 | set of dorsal interossei of left foot | `source-aggregate` |

The pinned v3 parts list and composite hierarchy provide no individually named dorsal-foot interosseous source elements. The cached v4 IS-A and PART-OF parts lists/element maps also contain no such individually named surfaces. After exact-coordinate seam welding, the v3 right-foot OBJ has four large connected components plus six small fragments; the left has four large components plus eighteen fragments. Connectivity alone does not establish ordinal anatomical labels or the ownership of small fragments, so those objects remain explicitly identified as groups. A validated split would need a reviewed component/fragment-to-ordinal mapping, or another appropriately licensed atlas with individual labels and verified registration. No ordinal labels are guessed here.

## Geometry and runtime contract

Root fields include `schemaVersion: 1`, `format: quantized-uint16-le`, `meshes`, binary length/SHA-256, companion asset hashes, source attribution, license and bounded coverage. Meshes remain compatible with the existing `decodeGeometry` function:

- `name` and `parent` equal the original regional mesh name; `bundle` is `body` or `muscles`.
- `nv`, `ni`, `min`, `size`, `offV`, `offI` use the existing little-endian Uint16 encoding. Offsets are bytes; `ni` is the index count.
- `frame`, `landmarks`, `side`, `cervical`, `layer` and `sourceFrame` retain the original parent values. Source-frame formulas are independently recalculated from pinned source reference points and must match exactly.
- Each `parts` entry has `id`, `name`, `kind: bone|muscle`, `side: L|R|null`, and `identityScope`.
- `start` and `count` are **index offsets/counts relative to this mesh**, both multiples of three. A raycaster triangle at `faceIndex` belongs to the part whose range contains `faceIndex * 3`.
- `firstVertex` and `vertexCount` specify an exclusive vertex interval. Every index in a part refers only to that part's interval. No vertices are shared between different source elements.
- `sourceTriangles`, `triangleBudget`, and `droppedDegenerateTriangles` record per-element simplification; optional whole-muscle/bone fields record grouping without replacing source identity.

Each original OBJ is seam-welded and simplified independently. Existing regional triangle budgets are allocated proportionally to source triangle counts, with a minimum allocation of 64 triangles per element (or the original count when smaller), using deterministic integer remainders. Only then are source surfaces concatenated into their parent's coordinate frame. Quantization-degenerate triangles are removed within their source element, followed by independent vertex compaction. No range is guessed after regional simplification, and no welding or simplification crosses source-element boundaries.

## Reproduction and verification

Use the environment pinned by `tools/requirements-body.txt`:

```sh
tools/.venv/bin/python tools/build_individual_body.py
tools/.venv/bin/python tools/build_individual_body.py --verify
npm test -- tests/unit/individual-body-assets.test.js
```

`--verify` rebuilds in memory and requires byte-for-byte equality of both outputs. Both build modes validate pinned input checksums, source coverage, exact names/sides, source hierarchy, parent frames, exclusive vertex ownership, contiguous triangle ranges, nondegenerate quantized triangles, finite bounded positions, index limits, regional budgets and complete binary coverage. All ten original companion asset hashes are checked before/after execution. The focused unit tests also use the real runtime decoder and check finite generated normals.

Verified output: 252,955 triangles (92,102 skeletal; 160,853 muscle), maximum 27,537 vertices per mesh, and at least 88 surviving triangles per source component. Fifteen quantization-degenerate triangles were removed. `individual-body.bin` is 2,292,534 bytes; JSON is 225,215 bytes; combined size is **2,517,749 bytes**, below the 3,000,000-byte budget. Binary SHA-256: `ee0e6abbe6e56ea6e1e538905202510d4d475f6eb8625e5c605e7ade9444e5f0`.

Geometry remains simplified reference anatomy with regional rigid motion. Exact source identity and a passing decoder do not establish patient-specific alignment, individual muscle deformation, anatomical measurement accuracy, clinical validation or live-camera behavior.
